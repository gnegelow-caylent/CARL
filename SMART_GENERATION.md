# CARL Smart Infrastructure Generation

**Status:** ✅ Production Ready (January 2026)

CARL now scans your AWS environment before generating infrastructure code and creates only what's missing. No more duplicate resources, no more manual variable configuration.

---

## 🎯 Overview

### The Problem (Before)

Traditional infrastructure-as-code generation:
- Generates **static code** regardless of what exists
- Requires **manual configuration** (`create_guardduty = false`)
- Tries to create **duplicate resources** (fails or requires imports)
- No awareness of **existing infrastructure**
- Users must **manually check** what exists before running code

### The Solution (Now)

CARL's smart generation:
- **Scans AWS environment** before generating any code
- **Detects existing resources** (GuardDuty, Security Hub, VPCs, etc.)
- **Generates only what's needed** (uses data sources for existing)
- **Zero manual configuration** (no create_XXX variables)
- **Clear feedback** on what exists vs what will be created

## 🔍 What CARL Detects

### Security Resources

| Resource | Detection Method | What CARL Finds |
|----------|------------------|-----------------|
| **GuardDuty** | `guardduty:ListDetectors` | Detector ID, enabled status |
| **Security Hub** | `securityhub:DescribeHub` | Hub ARN, enabled status |
| **AWS Config** | `config:DescribeConfigurationRecorders` | Recorder name, status |
| **CloudTrail** | `cloudtrail:DescribeTrails` | Trail name, bucket, multi-region status |

### Networking Resources

| Resource | Detection Method | What CARL Finds |
|----------|------------------|-----------------|
| **VPC** | `ec2:DescribeVpcs` (by Name tag) | VPC ID, CIDR block |
| **Subnets** | `ec2:DescribeSubnets` | Count, IDs, AZs |
| **NAT Gateways** | `ec2:DescribeNatGateways` | Count, availability |
| **Internet Gateway** | `ec2:DescribeInternetGateways` | Attached status |

### Storage Resources (Partial)

| Resource | Detection Method | What CARL Finds |
|----------|------------------|-----------------|
| **S3 Buckets** | Name-based lookup | Existence (not fully implemented) |

## 🚀 How It Works

### Step-by-Step Process

1. **User Request**
   ```
   /carl build security/soc2-stack
   ```

2. **Environment Scan**
   ```
   Scanning AWS environment for existing security resources...
   ```
   CARL calls AWS APIs to detect:
   - GuardDuty detectors
   - Security Hub status
   - AWS Config recorders
   - CloudTrail trails

3. **Detection Summary**
   ```
   ✓ GuardDuty already exists (detector: det-abc123)
   ✗ Security Hub not enabled (will create)
   ✗ AWS Config not found (will create)
   ✓ CloudTrail active (trail: my-trail)
   ```

4. **Smart Code Generation**
   - For **existing resources**: Generate `data` sources
   - For **missing resources**: Generate full `resource` blocks
   - **Always accurate outputs**: Reference correct resource

5. **User Feedback**
   - Show detection results in Slack
   - Display dynamic compliance notes
   - Provide adaptive deployment steps

    }

          enable = true
        }
      }

# ============================================================================

resource "aws_config_configuration_recorder" "main" {

    all_supported                 = true
    include_global_resource_types = true
  }
}

# ... full Config setup ...

# ============================================================================

# ============================================================================

data "aws_cloudtrail" "existing" {
  name = "org-trail"
}

# Existing trail: org-trail

# ============================================================================

# ============================================================================

output "guardduty_detector_id" {

## 🛠️ Technical Implementation

### Architecture

```
User Request (/carl build security/soc2-stack)
    ↓
InfrastructureBuilder.__init__()
    ↓
ResourceDetector(region="us-east-1")
    ↓
detect_security_resources()
    ├─ guardduty.list_detectors()
    ├─ securityhub.describe_hub()
    ├─ config.describe_configuration_recorders()
    └─ cloudtrail.describe_trails()
    ↓
SecurityResourcesStatus
    ├─ guardduty_exists: bool
    ├─ guardduty_detector_id: str
    ├─ security_hub_exists: bool
    ├─ config_exists: bool
    └─ cloudtrail_exists: bool
    ↓
Dynamic Code Generation
    ├─ if exists: _gen_XXX_data_source()
    └─ if missing: _gen_XXX_tf()
    ↓
GeneratedInfrastructure
    ├─ terraform_code (smart)
    ├─ compliance_notes (dynamic)
    └─ deployment_steps (adaptive)
```

## 🔐 IAM Permissions Required

CARL's Lambda execution role needs these additional read permissions:

```json
{
  "Version": "2012-10-17",
  "Statement": [
    {
      "Effect": "Allow",
      "Action": [
        "guardduty:ListDetectors",
        "securityhub:DescribeHub",
        "config:DescribeConfigurationRecorders",
        "cloudtrail:DescribeTrails",
        "ec2:DescribeVpcs",
        "ec2:DescribeSubnets",
        "ec2:DescribeNatGateways",
        "ec2:DescribeInternetGateways"
      ],
      "Resource": "*"
    }
  ]
}
```

**Security Notes:**
- All permissions are **read-only** (Describe/List only)
- No write or destructive actions
- Scans are logged in CloudWatch
- No secrets or credentials accessed

## 🐛 Known Limitations

### Current Limitations

1. **Single Region** - Only scans the configured region (default: us-east-1)
2. **Name-Based VPC Detection** - VPCs detected by Name tag only
3. **No Multi-Account Scanning** - Scans current account only
4. **No State Import** - Detects but doesn't import to Terraform state
5. **S3 Detection Partial** - Not fully implemented for buckets

### Intentional Design Choices

1. **Always Fresh Scans** - No caching (ensures accuracy)
2. **Read-Only** - Never modifies existing resources
3. **No Assumptions** - If can't detect, generates create code
4. **Fail Safe** - On API errors, assumes resource doesn't exist

## 🆘 Troubleshooting

### "CARL created a resource that already exists"

**Cause:** Detection failed (API permissions or error)

**Solution:**
1. Check Lambda IAM role has List/Describe permissions
2. Check CloudWatch logs for API errors
3. Verify resource is in the same region as CARL

### "CARL says resource exists but I don't see it"

**Cause:** Resource in different region or account

**Solution:**
1. Verify CARL's configured region matches your resource
2. Check you're in the correct AWS account
3. Verify resource naming matches CARL's detection logic

### "Generated code references wrong resource"

**Cause:** Bug in output generation logic

**Solution:**
1. Report issue with detection results from logs
2. Workaround: Manually adjust outputs
3. File bug report with CARL team
